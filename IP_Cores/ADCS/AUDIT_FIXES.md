# ADCS — audit 2026-11 fixes

Regression: `sim/run_regression.sh`. It runs layers L1a–L4 plus the new
`run_audit.sh`.

## Baseline (before changes, run on a frozen git copy)

L1a FMA, L1b dot, L1c engine, L2 regfile, L2 DMA, L3 top and L4 SoC: 7/7 PASS. The Vivado scripts (`vivado/*.tcl`) are
Vivado only and were not run. They were updated, see below.

## Findings and changes

| Sev | Finding | Change | Verification |
|---|---|---|---|
| ALTA (ASIC) | The whole FP path depended on the Xilinx FPO (`fp_fma`). The behavioural `fp32_fma` (480-bit single-stage accumulator) cannot be synthesized. | New **`rtl/fp32_fma_rtl.vhd`**: portable, synthesizable, pipelined binary32 FMA. It is fused with a single RNE rounding. Its numeric contract is **bit-exact with `fp32_pkg.fma_fp32`**: FTZ on inputs and outputs (after rounding), canonical qNaN, Inf*0 and Inf-Inf → qNaN, exact cancellation → +0, sign rules for zero products, overflow → ±Inf. Stages: S1 unpack, specials and 24×24 product; S2 alignment in a 78-bit window plus a 79-bit add/sub; S3 LZC and normalize; S4 round and pack. Latency = `LAT_FMA` (≥4: 4 compute stages plus LAT_FMA−4 output registers), throughput 1/cycle, MUT 1/2/3 kept. `fp32_fma.vhd` is now a selector, generic `IMPL`, default from `fp32_cfg_pkg`: **RTL (default, ASIC + sim)**, XIL (FPO wrapper, now entity `fp32_fma_xil`), BEHAV (reference, sim only). The FPGA flow compiles `fp32_cfg_pkg_xil.vhd` instead of `fp32_cfg_pkg.vhd`. Every solver layer (L1b–L4) now runs on the RTL FMA. | `tb_fp32_fma_rtl`: **250 036 vectors, 0 mismatches** at LAT=8 (8 random classes + 36 directed corners), 20 036 at LAT=4, latency checked, MUT 1/2/3 all detected. L1a's 20 436 oracle vectors also pass through the RTL FMA. `ghdl --synth` of `fp32_fma` and `adcs_accel_top` succeeds. |
| MEDIA | `axi_dma_engine` ignored RRESP/BRESP and had no timeout | On xRESP ≠ OKAY the beat is not written and the command ends with `cmd_done` + `cmd_err` (`:244,314`). A watchdog (generic `WDOG`, 4096) per AXI handshake aborts the command with `err_code`=10 (`:340`). The sequencer goes to `T_ERROR`, which sets STATUS.ERR + DONE (`adcs_accel_top.vhd:363`). | tb_adcs_audit T1, T3 |
| MEDIA | `mpc_engine`: maxiter=0 and n_dim=0 wrap around | Regfile clamps NDIM to 1..**D** (`adcs_regfile.vhd:148`) and MAXITER to ≥1, saturating at 65535 (`:156`). Read-back returns the clamped value. D=70, not DP=72: H has D columns and the U mirror D entries, so n_dim 71/72 would have indexed past those arrays. The engine itself also finishes immediately on 0 (`mpc_engine.vhd:222`) and clamps n_dim>D (`:124`). Bank reads and writes with row/address ≥ DP are guarded (`adcs_mem_banks.vhd:51,89,138`). | tb_adcs_audit T4, tb_mpc_guard, L2 regfile (oracle updated) |
| BAJA | NaN in clamp saturated silently | A NaN result is propagated into U and flagged (`nan_err`, `mpc_engine.vhd:158`), which sets STATUS.ERR at the end of the operation. ±Inf is still clamped. | tb_adcs_audit T5 |
| BAJA | Soft reset killed the DMA in the middle of a handshake | The DMA is no longer reset by the soft reset. It gets `abort` (`adcs_accel_top.vhd:236`) and stops at a safe point (`axi_dma_engine.vhd:226,261,279,316`): an issued AR/AW is completed (R beat, or W + B). The sequencer only issues commands to an idle DMA, and STATUS.BUSY covers the drain (`:260`). | tb_adcs_audit T2 (AXI protocol checker) |
| ALTA (from ECC) | CPU stores to local RAM dropped during DMA; dma_burst 9-bit LEN vs 8-bit AxLEN; LEN=0 | Same fix as ECC_Scrubber in `rtl/mem_subsys_dma_adcs.vhd:249` (core stalled on a local store while the DMA owns the port), `:217,227` and `soc/dma_burst.vhd`. | tb_dma_audit_adcs D1–D3 |
| (found) | `irq` was assigned only in the async-reset branch, so it synthesized to a latch (`ghdl --synth` error) | `irq <= '0'` concurrent (`adcs_accel_top.vhd:165`). | ghdl --synth OK |

Oracle: `model/regfile_model.py` now models the NDIM/MAXITER clamps from the
spec, with a new sequence section 7. The tracked `sim/work_l2/regseq.txt` is
regenerated by `run_l2_regfile.sh` and therefore changes. The solver oracle
`mpc_oracle.py` was not changed: the regression vectors never produce NaN.
NaN propagation is specified and checked by tb_adcs_audit.

TB hardening: `tb_axi_dma_engine.vhd` now counts AXI address handshakes per
command. MUT2 (one extra beat) used to be detected only because GHDL crashed
on `g_bank(DP)` out of range. The new bank guards remove that crash, so the
extra beat is now caught on the bus.

Vivado: `vivado/bd_adcs_steps.tcl` adds `fp32_cfg_pkg_xil.vhd`,
`fp32_fma_xil.vhd`, `fp32_fma_rtl.vhd` and `fp32_fma.vhd`.
`vivado/run_synth_adcs.tcl` no longer removes `fp32_fma.vhd`. It checks that
only one configuration package is present.

## New tests (`sim/run_audit.sh`)

`tb_fp32_fma_rtl` (N_RAND=200000 by default; 250 000 was run), LAT=4, MUT 1–3,
`tb_adcs_audit` T1–T6, `tb_mpc_guard`, `tb_dma_audit_adcs`.
On the pre-audit RTL: tb_adcs_audit fails at T4 (and T1, T2 protocol
violation, T3 deadlock when run individually), and tb_mpc_guard fails (out-of-range).

## Final status

`run_regression.sh` after the changes: L1a (T=81819000000 fs, oracle signature
0x873BA7B4 through the RTL FMA), L1b, L1c, L2 regfile, L2 DMA, L3
(T=448446000000 fs) and L4 SoC (firmware signature bit-identical,
T=227667000000 fs) all PASS, with every layer now running on the RTL FMA.
run_audit also passes (tb_fp32_fma_rtl 200k, LAT=4, MUT 1-3 detected,
tb_adcs_audit, tb_mpc_guard, tb_dma_audit_adcs). The L1–L4 end timestamps
are identical to the baseline (except L2 regfile and L2 DMA, whose benches
were extended).

## Not fixed / notes

- `fp32_fma_rtl` uses one 24×24 multiplier stage. At high clocks on SG13G2 the
  multiplier will likely need a second stage. Retiming of the LAT_FMA−4 output
  registers can take care of it, and the latency contract allows it (no
  synthesis timing was run here).
- The Vivado flow pulls the RV32 SoC sources (`dma_burst.vhd`,
  `cpu_pipeline.vhd`, ...) from `~/rv32i`, not from `ADCS/soc/`. The
  `soc/dma_burst.vhd` fix only reaches silicon if `~/rv32i` gets it too (outside
  this scope).
- `ADCS/soc/cpu_pipeline.vhd` lacks the write-back history forwarding fix that
  `ECC_Scrubber/cpu_pipeline.vhd` has. Not part of the findings; reported only.
- The watchdog abort drops VALID before READY, which breaks the AXI protocol.
  This is only acceptable for a dead slave, and the interconnect then needs a reset.
- Board validation needed: FPO-vs-RTL equivalence on silicon (run the L4
  firmware with both cfg packages), soft reset during real NoC traffic, and an
  SLVERR/DECERR path from the Versal NoC.
